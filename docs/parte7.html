7  Importación y exploración de datos bioinformáticos en R

7.1 Introducción

En la sesión anterior aprendimos a crear objetos, utilizar estructuras de control y escribir funciones. Ahora trabajaremos con información que ya está guardada en archivos. El objetivo no es volver a estudiar BLAST ni aprender a ejecutar herramientas bioinformáticas: utilizaremos archivos con una estructura parecida a sus resultados para aprender a leerlos, reconocer sus columnas y explorar su contenido desde R.

Al finalizar podrás identificar la estructura de un archivo, importar tablas con R base y con readr, explorar su contenido, reconocer problemas frecuentes de lectura y extraer información sencilla sin modificar los archivos originales.

ImportanteAntes de comenzar

Los datos de esta sesión son sintéticos. Los valores de identidad, E-value y puntuación son ilustrativos; no representan resultados reales de una búsqueda BLAST ni deben utilizarse para inferencias biológicas.

7.2 Archivos de trabajo

Descarga y descomprime datos_sesion_02_blast.zip. Dentro de tu proyecto de RStudio crea data_raw/ y coloca ahí la carpeta descomprimida. Tendrás, entre otros, los archivos:

│   └── datos_sesion_02_blast/

└── scripts/

Los ejemplos utilizan rutas relativas a la raíz del proyecto. Si guardas los archivos en otra carpeta, modifica las rutas.

7.4 Importación de archivos tabulares

Una tabla tiene filas (registros) y columnas (variables o atributos). En nuestro ejemplo, cada fila representa un resultado de alineamiento y contiene identificadores y valores asociados. Importar significa interpretar correctamente esa estructura y convertirla en un objeto de R.

7.4.2 Importación con readr

readr ofrece funciones equivalentes, mensajes sobre los tipos de columnas y herramientas para detectar problemas de lectura. Instálalo una sola vez si aún no lo tienes; después cárgalo en cada sesión donde lo utilices.

Código 
#install.packages("readr")  # Solo si no está instalado
library(readr)
Código 
blast <- readr::read_tsv(
  "data_raw/datos_sesion_02_blast/resultados_blast.tsv",
  show_col_types = FALSE
)

metadata <- readr::read_csv(
  "data_raw/datos_sesion_02_blast/metadata_secuencias.csv",
  col_types = readr::cols(codigo_muestra = readr::col_character()),
  show_col_types = FALSE
)

En este caso, read_tsv() devuelve un tibble, una versión moderna del data.frame. La diferencia no es el contenido biológico, sino ciertas características de impresión y comportamiento en R.

Código

[1] "spec_tbl_df" "tbl_df"      "tbl"         "data.frame"
Código

[1] "spec_tbl_df" "tbl_df"      "tbl"         "data.frame"
R base readr Uso
read.csv() read_csv() Archivos separados por comas
read.delim() read_tsv() Archivos separados por tabulaciones
read.table() read_delim() Archivos con separador configurable

No es necesario utilizar ambos sistemas simultáneamente. Los comparamos para que puedas leer código escrito por otras personas; en las siguientes prácticas usaremos principalmente readr.

7.4.3 Encabezados, comentarios y valores faltantes

Algunos archivos tienen líneas explicativas antes de la tabla. Por ejemplo, blast_comentarios.tsv comienza con dos líneas que llevan #.

  • La función str(blast) permite consultar la estructura de un objeto en R, mostrando el tipo de objeto, sus dimensiones, los nombres de las columnas, sus tipos de datos y algunos de sus valores.

  • La función readr::spec() permite consultar las especificaciones de las columnas de un conjunto de datos importado con readr, especialmente los tipos de datos que se asignaron durante la lectura del archivo.

  • La función readr::problems(blast) permite identificar problemas detectados durante la importación de los datos con readr, como valores que no corresponden al tipo de dato esperado. Si no se detectaron problemas, devuelve una tabla vacía.

7.6 Cuando una importación no sale como esperamos

Los problemas más comunes suelen ser de formato, no de biología. Veamos cómo reconocerlos antes de seguir trabajando.

7.6.1 Separador equivocado

Código 
ruta <- "data_raw/datos_sesion_02_blast/blast_separador_incorrecto.csv"
mal <- readr::read_csv(ruta, show_col_types = FALSE)
names(mal)
[1] "query_id\tsubject_id\tpident\tlength\tevalue\tbitscore"
Código 
bien <- readr::read_tsv(ruta, show_col_types = FALSE)
names(bien)
[1] "query_id"   "subject_id" "pident"     "length"     "evalue"    
[6] "bitscore"

Si la primera lectura genera una sola columna que contiene tabulaciones, el separador es incorrecto. La solución no es renombrar el archivo, sino elegir la función de lectura adecuada.

7.6.2 Identificadores que parecen números

Un identificador como 001 no necesariamente representa el número 1. Si se convierte a número, pierde los ceros iniciales. Por eso conviene declarar su tipo como carácter cuando sea necesario.

Código 
metadata <- readr::read_csv(
  "data_raw/datos_sesion_02_blast/metadata_secuencias.csv",
  col_types = readr::cols(codigo_muestra = readr::col_character()),
  show_col_types = FALSE
)
metadata$codigo_muestra
[1] "001" "002" "003" "004" "005" "006" "007" "008"

7.6.3 Ausencias y registros repetidos

Código 
blast_na <- readr::read_tsv(
  "data_raw/datos_sesion_02_blast/blast_valores_faltantes.tsv",
  show_col_types = FALSE
)
colSums(is.na(blast_na))
  query_id subject_id     pident     length     evalue   bitscore 
         0          0          1          0          0          0
Código 
anyDuplicated(blast_na)
[1] 0
Código 
anyDuplicated(blast_na$query_id)
[1] 2

anyDuplicated(blast_na$query_id) puede devolver un índice distinto de cero, porque varias filas comparten la misma consulta. No debemos confundir identificadores repetidos con filas duplicadas: cada fila puede describir un alineamiento diferente.

PrecauciónNo corrijas datos sin conocer su significado

Evita borrar filas, reemplazar NA por cero o convertir columnas indiscriminadamente. Primero revisa la documentación del archivo y qué representa cada valor.

7.7 Una mirada breve a FASTA desde R

FASTA es un formato de texto utilizado para almacenar secuencias. Aquí no construiremos un analizador completo de FASTA ni utilizaremos paquetes especializados: solo aprovecharemos funciones de texto para reconocer su estructura.

Código 
lineas <- readLines("data_raw/datos_sesion_02_blast/secuencias.fasta")
head(lineas, 6)
[1] ">seq01 secuencia_sintetica"                                   
[2] "AACTCGTAGCAGTACGGATCAACTGTTATAAAATGCACCGAGATTGGTGCGAACG"      
[3] ">seq02 secuencia_sintetica"                                   
[4] "GACAATCATGTACAGTCACGAGTCCGCAAAACTCCAATTGGAGCAAGCGCTCGGTGTC"   
[5] ">seq03 secuencia_sintetica"                                   
[6] "CCCCGGTGGAGAGGTCCAAGGTCACAAAGGTTTCAAACGAATTGAGAATCCAGGCGATTAA"

Las líneas que comienzan con > contienen encabezados. Podemos localizarlas con grep():

Código 
encabezados <- grep("^>", lineas, value = TRUE)
encabezados
[1] ">seq01 secuencia_sintetica" ">seq02 secuencia_sintetica"
[3] ">seq03 secuencia_sintetica" ">seq04 secuencia_sintetica"
[5] ">seq05 secuencia_sintetica" ">seq06 secuencia_sintetica"
[7] ">seq07 secuencia_sintetica" ">seq08 secuencia_sintetica"
Código 
length(encabezados)
[1] 8

El símbolo ^ indica el inicio de la línea y > es el carácter que buscamos. Este ejemplo funciona incluso si un archivo FASTA contiene secuencias repartidas en varias líneas, porque solo estamos contando encabezados, no intentando reconstruir las secuencias.
