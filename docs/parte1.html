1  De Bash a R: programación para bioinformática

TipObjetivos de aprendizaje

Al finalizar la sesión podrás:

  1. Trabajar con scripts y objetos en R y reconocer las diferencias esenciales con Bash.
  2. Utilizar vectores, listas y data.frame para representar datos biológicos.
  3. Seleccionar registros, construir funciones y recorrer colecciones de datos.
  4. Instalar, cargar y consultar paquetes de R.
  5. Integrar un script de R a un repositorio bioinformático que ya utiliza Git.
NotaPunto de partida

Ya conoces terminal de Linux, Git/GitHub, Markdown, procedencia de datos, FASTA, BED, alineamientos y anotaciones. No repetiremos esos temas: los usaremos como contexto para aprender la sintaxis y la forma de trabajo de R. No se requieren conocimientos de estadística.

2 Material previo opcional: instalación y preparación del entorno

NotaAntes de la primera sesión · No cuenta dentro de las dos horas

Realiza esta preparación solo si todavía no tienes R y las herramientas necesarias. No es necesario reinstalar programas que ya funcionan. Las instrucciones varían según el sistema operativo. Si utilizas un clúster compartido, sigue primero las indicaciones de sus administradores.

2.1 ¿Qué son R, RStudio y las herramientas de compilación?

  • R es el lenguaje y el entorno que ejecuta los análisis.
  • RStudio Desktop es un entorno de desarrollo (IDE) para editar scripts, trabajar con proyectos y ejecutar R; no sustituye la instalación de R.
  • Las herramientas de compilación permiten instalar paquetes desde su código fuente cuando no existe un binario apropiado o cuando el paquete requiere compilación. No todos los paquetes las necesitan.

2.2 Windows: R, RStudio y Rtools

  1. Descarga e instala R desde https://cran.r-project.org/bin/windows/base/.
  2. Descarga e instala RStudio Desktop desde https://posit.co/download/rstudio-desktop/.
  3. Consulta https://cran.r-project.org/bin/windows/Rtools/ e instala la versión de Rtools compatible con tu versión de R. No elijas una versión al azar: CRAN indica las correspondencias.
  4. Reinicia RStudio después de instalar las herramientas, si ya estaba abierto.

Verificación de Rtools (desde la consola de R):

Código 
install.packages("pkgbuild")  # Solo si aún no está instalado
pkgbuild::check_build_tools(debug = TRUE)

Si la verificación falla, revisa las instrucciones de CRAN para la versión instalada de R y Rtools antes de modificar manualmente variables como PATH.

2.3 macOS: R, RStudio y herramientas de desarrollo

  1. Instala la versión de R correspondiente a tu equipo desde https://cran.r-project.org/bin/macosx/ (verifica si es Apple Silicon o Intel).
  2. Instala RStudio Desktop desde https://posit.co/download/rstudio-desktop/.
  3. En la terminal de macOS, instala las herramientas de línea de comandos de Xcode:
Código 
xcode-select --install
  1. Algunos paquetes que compilan código Fortran requieren GNU Fortran además de las herramientas anteriores. Consulta las versiones y las indicaciones oficiales en https://mac.r-project.org/tools/; deben ser compatibles con tu instalación de R.

No hace falta instalar Xcode completo para la mayoría de las tareas de compilación de paquetes de R.

2.4 Linux: R y compiladores del sistema

En Ubuntu o Debian, si tienes permisos de administración y todavía no están instalados, puedes ejecutar en la terminal:

Código 
sudo apt update
sudo apt install -y r-base r-base-dev build-essential gfortran

Después puedes instalar RStudio Desktop desde https://posit.co/download/rstudio-desktop/ si deseas utilizarlo.

En otras distribuciones (Fedora, Arch, etc.), los nombres de los paquetes y los comandos del gestor de paquetes son diferentes. Algunas bibliotecas adicionales (libcurl, libxml2, libssl, entre otras) pueden ser necesarias solo para determinados paquetes de R.

En un clúster o servidor compartido, no ejecutes sudo ni intentes instalar paquetes globales sin autorización. Comprueba si R está disponible:

Código 
R --version
Rscript --version
# En sistemas que usan módulos, consulta la documentación local:
module avail R

2.6 Instalar y cargar paquetes de R

Un paquete se instala una vez por entorno o biblioteca; se carga con library() en cada sesión en la que se necesita. No incluyas install.packages() en scripts de análisis que deban ejecutarse repetidamente.

Código 
# Ejecutar en la consola, una vez por entorno:
install.packages(c("readr", "dplyr", "tidyr", "ggplot2", "purrr", "here"))

# En los scripts, cargar los paquetes necesarios:
library(readr)
library(dplyr)

# También se puede llamar una función con paquete::función:
# readr::read_tsv("data_raw/anotaciones.tsv")

Para comprobar las herramientas de compilación de tu sistema, cuando corresponda:

Código 
if (!requireNamespace("pkgbuild", quietly = TRUE)) {
  install.packages("pkgbuild")
}
pkgbuild::check_build_tools(debug = TRUE)

2.8 Objetos y estructuras de datos

2.8.1 Tipos básicos y vectores

En R, un vector atómico contiene elementos del mismo tipo. Los índices comienzan en 1, no en 0.

Código 
ids <- c("genA", "genB", "genC", "genD")
longitudes <- c(150, 320, 90, 210)
anotado <- c(TRUE, FALSE, TRUE, TRUE)

class(ids)
[1] "character"
Código 
length(ids)
[1] 4
Código 
ids[1]
[1] "genA"
Código 
ids[c(2, 4)]
[1] "genB" "genD"
Código 
longitudes[longitudes >= 200]
[1] 320 210

Las comparaciones producen vectores lógicos que pueden utilizarse para seleccionar elementos. Los valores faltantes se representan con NA.

Código 
longitudes2 <- c(150, NA, 90)
is.na(longitudes2)
[1] FALSE  TRUE FALSE
Código 
longitudes2[!is.na(longitudes2)]
[1] 150  90

2.8.2 Tablas: data frames

Un data.frame representa una tabla cuyas columnas pueden tener tipos diferentes. Aquí cada fila corresponde a un gen.

Código 
anotaciones <- data.frame(
  gen = c("g1", "g2", "g3", "g4"),
  longitud = c(450, 120, 800, 300),
  producto = c("transportador", "hipotetica", "enzima", "enzima"),
  stringsAsFactors = FALSE
)
anotaciones
  gen longitud      producto
1  g1      450 transportador
2  g2      120    hipotetica
3  g3      800        enzima
4  g4      300        enzima
Código 
str(anotaciones)
'data.frame':   4 obs. of  3 variables:
 $ gen     : chr  "g1" "g2" "g3" "g4"
 $ longitud: num  450 120 800 300
 $ producto: chr  "transportador" "hipotetica" "enzima" "enzima"
Código 
anotaciones$gen
[1] "g1" "g2" "g3" "g4"
Código 
anotaciones[anotaciones$producto == "enzima", ]

Recuerda la diferencia entre seleccionar una columna (anotaciones$gen), una fila (anotaciones[2, ]) y una celda (anotaciones[2, 3]).

2.8.3 Listas

Una lista puede almacenar objetos de tipos y tamaños diferentes, por ejemplo secuencias, metadatos y una tabla de resultados.

Código 
muestra <- list(
  id = "M01",
  secuencias = c("ATGCGT", "ATTA", "GGCCATG"),
  anotaciones = anotaciones
)
muestra$id
[1] "M01"
Código 
muestra$secuencias
[1] "ATGCGT"  "ATTA"    "GGCCATG"
Código 
muestra[["anotaciones"]]
  gen longitud      producto
1  g1      450 transportador
2  g2      120    hipotetica
3  g3      800        enzima
4  g4      300        enzima
ImportanteNo confundir

Un vector atómico, una lista y un data.frame no son equivalentes. Elegir la estructura apropiada facilita el procesamiento y evita conversiones innecesarias.

2.9 Operaciones, indexación y funciones

2.9.1 Trabajar con secuencias como cadenas de caracteres

Usaremos secuencias cortas para practicar funciones de R; esto no reemplaza herramientas especializadas para archivos FASTA grandes.

Código 
secuencias <- c(
  genA = "ATGCCGTAA",
  genB = "CCGTTAGG",
  genC = "ATGATGCC"
)

nchar(secuencias)                 # Longitud de cada cadena
genA genB genC 
   9    8    8
Código 
grepl("ATG", secuencias)        # ¿Contiene el patrón literal?
[1]  TRUE FALSE  TRUE
Código 
names(secuencias)[grepl("ATG", secuencias)]
[1] "genA" "genC"

grepl() devuelve un vector lógico; grep() devuelve posiciones (o valores con argumentos adicionales). Encontrar ATG no basta para identificar genes funcionales ni validar un marco de lectura.

2.9.2 Definir funciones

Código 
contiene_motivo <- function(secuencia, motivo = "ATG") {
  grepl(motivo, secuencia, fixed = TRUE)
}

contiene_motivo("CCATGTT")
[1] TRUE
Código 
contiene_motivo("CCATGTT", "TGA")
[1] FALSE

Una función recibe argumentos, realiza operaciones y devuelve un resultado. Los nombres de los argumentos deben expresar qué información espera la función.

NotaEjercicio 2. Una función reutilizable (7 min)

Escribe una función es_adn_simple() que reciba una cadena y devuelva TRUE si contiene únicamente las letras A, C, G y T (en mayúsculas). Prueba con "ACGT", "ACNT" y "ACGTX". Para este ejercicio no consideres símbolos de ambigüedad IUPAC.

Pista: grepl() acepta expresiones regulares; ^[ACGT]+$ describe una o más letras válidas desde el principio hasta el final.

TipSolución · Ejercicio 2
Código 
es_adn_simple <- function(secuencia) {
  grepl("^[ACGT]+$", secuencia)
}

es_adn_simple("ACGT")
[1] TRUE
Código 
es_adn_simple("ACNT")
[1] FALSE
Código 
es_adn_simple("ACGTX")
[1] FALSE

Esta función comprueba un criterio deliberadamente restringido; secuencias reales pueden utilizar códigos de ambigüedad.

2.10 Condiciones e iteración

2.10.1 Condiciones

Código 
clasificar_longitud <- function(n) {
  if (is.na(n)) {
    return("desconocida")
  }
  if (n >= 300) {
    "larga"
  } else {
    "corta"
  }
}

clasificar_longitud(450)
[1] "larga"
Código 
clasificar_longitud(120)
[1] "corta"

Los umbrales de este ejemplo son arbitrarios y didácticos; no representan categorías biológicas universales.

2.10.2 Ciclos y funciones de aplicación

Código 
for (id in names(secuencias)) {
  cat(id, ": ", nchar(secuencias[[id]]), " nt\n", sep = "")
}
genA: 9 nt
genB: 8 nt
genC: 8 nt
Código 
# Una alternativa vectorizada:
nchar(secuencias)
genA genB genC 
   9    8    8
Código 
# Aplicar una función a los elementos de una lista:
lapply(as.list(secuencias), contiene_motivo)
$genA
[1] TRUE

$genB
[1] FALSE

$genC
[1] TRUE
Código 
# Simplificar a un vector lógico:
sapply(as.list(secuencias), contiene_motivo)
 genA  genB  genC 
 TRUE FALSE  TRUE

En R no siempre necesitamos escribir un ciclo explícito. Más adelante conoceremos purrr::map() para trabajar de manera consistente con colecciones de archivos y resultados.

NotaEjercicio 3. Comparar estrategias (6 min)

A partir de secuencias, construye un vector lógico que indique qué secuencias contienen ATG de dos formas: (a) mediante un ciclo for y (b) mediante vapply(). Verifica que los resultados sean iguales.

TipSolución · Ejercicio 3
Código 
resultado_for <- setNames(logical(length(secuencias)), names(secuencias))
for (i in seq_along(secuencias)) {
  resultado_for[i] <- contiene_motivo(secuencias[[i]])
}

resultado_apply <- vapply(secuencias, contiene_motivo, logical(1))
identical(resultado_for, resultado_apply)
[1] TRUE

vapply() exige que la función devuelva el tipo y tamaño indicados (logical(1)), lo que puede ayudar a detectar errores.

2.11 Scripts, paquetes y proyectos RStudio

Ya conoces directorios, rutas relativas y Git. Ahora veamos cómo se integran con R:

proyecto-bioinfo/
├── proyecto-bioinfo.Rproj
├── README.md
├── .gitignore
├── data_raw/
├── R/
│   └── funciones.R
├── scripts/
│   └── 01_resumen.R
└── results/

Abre un proyecto existente mediante File > New Project o crea uno nuevo en una carpeta versionada. Un archivo .Rproj almacena opciones del proyecto; no reemplaza a Git.

Código 
# Ejemplo dentro de scripts/01_resumen.R
source("R/funciones.R")

datos <- read.delim("data_raw/anotaciones.tsv")
# Validar columnas antes de procesar:
stopifnot(all(c("gen", "longitud") %in% names(datos)))

write.table(datos, "results/anotaciones_revisadas.tsv",
            sep = "\t", row.names = FALSE, quote = FALSE)

Las rutas del ejemplo se interpretan desde la raíz del proyecto. Si ejecutas Rscript scripts/01_resumen.R desde otra carpeta, el directorio de trabajo puede ser diferente. Para un flujo robusto, acuerda explícitamente desde dónde se ejecutan los scripts o utiliza herramientas de rutas basadas en la raíz del proyecto.

readr::write_tsv(seleccion, "results/genes_seleccionados.tsv")

2.12 Actividad integradora

NotaReto. Un resumen de secuencias en R

Recibes las siguientes secuencias, que ya se consideran extraídas de un archivo FASTA:

Código 
secuencias_reto <- c(
  seq01 = "ATGCGTAA",
  seq02 = "CCGTTAGC",
  seq03 = "ATGATGCC",
  seq04 = "TTTTGGCA",
  seq05 = "GGATGCCC"
)

Construye un script que:

  1. Guarde los identificadores y secuencias en una tabla.
  2. Agregue una columna con la longitud de cada secuencia.
  3. Agregue una columna lógica que indique si contiene el motivo literal ATG.
  4. Seleccione las secuencias que contienen el motivo.
  5. Muestre cuántas secuencias cumplen la condición.
  6. Opcional: guarde la tabla completa en un archivo TSV dentro de results/.

Antes de programar, escribe dos líneas que describan entrada → procesamiento → salida. Al finalizar, comprueba manualmente al menos una fila.

TipSolución · Actividad integradora
Código 
resumen <- data.frame(
  id = names(secuencias_reto),
  secuencia = unname(secuencias_reto),
  stringsAsFactors = FALSE
)
resumen$longitud <- nchar(resumen$secuencia)
resumen$tiene_ATG <- grepl("ATG", resumen$secuencia, fixed = TRUE)

seleccion <- resumen[resumen$tiene_ATG, ]
print(resumen)
     id secuencia longitud tiene_ATG

2 seq02  CCGTTAGC        8     FALSE
3 seq03  ATGATGCC        8      TRUE
4 seq04  TTTTGGCA        8     FALSE
5 seq05  GGATGCCC        8      TRUE
Código 
print(seleccion)
     id secuencia longitud tiene_ATG
1 seq01  ATGCGTAA        8      TRUE
3 seq03  ATGATGCC        8      TRUE
5 seq05  GGATGCCC        8      TRUE
Código 
cat("Secuencias con ATG:", sum(resumen$tiene_ATG), "\n")
Secuencias con ATG: 3
Código 
# Guardado opcional:
# dir.create("results", showWarnings = FALSE)
# write.table(resumen, "results/resumen_secuencias.tsv",
#             sep = "\t", row.names = FALSE, quote = FALSE)

Entrada: vector nombrado de secuencias. Procesamiento: obtener longitudes y buscar un patrón literal. Salida: tabla anotada y subconjunto de coincidencias.

Interpretación: la coincidencia de un motivo corto no permite inferir por sí sola función biológica, ortología o expresión.
