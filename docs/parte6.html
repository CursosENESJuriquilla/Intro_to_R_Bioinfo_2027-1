6  Scripts, paquetes y proyectos de RStudio

Hasta ahora hemos ejecutado instrucciones para crear objetos, utilizar estructuras de control y definir funciones. El siguiente paso es organizar esas instrucciones en un programa que pueda ejecutarse completo, en lugar de depender de comandos aislados en la consola.

6.1 ¿Qué es un script de R?

Un script es un archivo de texto con extensión .R que contiene una secuencia organizada de instrucciones. No basta con guardar comandos en un archivo: un script útil debe indicar qué necesita para funcionar, qué operaciones realiza y qué resultados produce.

Ya aprendimos a crear archivos .R desde el editor de RStudio y a ejecutar líneas con Run o Ctrl + Enter (Windows/Linux) y Cmd + Enter (macOS). Ahora nos interesa aprender a estructurar su contenido.

Un script de análisis suele tener las siguientes partes:

  1. Descripción: propósito del programa y, cuando sea pertinente, autoría y fecha.
  2. Dependencias: paquetes y funciones que se utilizarán.
  3. Datos de entrada: objetos o archivos necesarios.
  4. Procesamiento: operaciones, condiciones, ciclos o llamadas a funciones.
  5. Resultados: objetos, tablas o archivos que se obtienen.

Estas partes no son reglas obligatorias del lenguaje, sino una forma de escribir código más claro y fácil de revisar.

6.2 Ejemplo: organizar un análisis de secuencias

Supongamos que recibimos identificadores de muestras y secuencias de ADN. Queremos construir una tabla que indique cuáles secuencias contienen caracteres válidos y cuál es su longitud.

Podríamos ejecutar los comandos uno por uno en la consola. Sin embargo, si guardamos el procedimiento en un script, podemos repetirlo sin reconstruir manualmente los objetos.

Código 
# --------------------------------------------------
# Análisis básico de secuencias de ADN
# Objetivo: revisar secuencias y resumir longitudes
# --------------------------------------------------

# 1. Datos de entrada
muestras <- c("M01", "M02", "M03", "M04")
secuencias <- c("ATGCCG", "ATNNGA", "GGCTTA", "ATG")

# 2. Verificar que hay un identificador por secuencia
stopifnot(length(muestras) == length(secuencias))

# 3. Procesar los datos
longitudes <- nchar(secuencias)
secuencia_valida <- grepl("^[ACGT]+$", secuencias)

# 4. Organizar y mostrar los resultados
resumen <- data.frame(
  muestra = muestras,
  secuencia = secuencias,
  longitud = longitudes,
  valida = secuencia_valida
)

print(resumen)
  muestra secuencia longitud valida
1     M01    ATGCCG        6   TRUE
2     M02    ATNNGA        6  FALSE
3     M03    GGCTTA        6   TRUE
4     M04       ATG        3   TRUE

Observa que el script define sus propios datos de entrada, comprueba una condición importante y construye el resultado. No necesita que muestras o secuencias existan previamente en el panel Environment.

Nota¿Qué cambia cuando trabajamos con archivos reales?

En un análisis bioinformático, normalmente los datos no se escribirán directamente en el script. Se leerán desde archivos como .csv o .tsv. La estructura del programa será similar, pero sustituiremos la definición manual de los datos por instrucciones de importación. Esto lo veremos en la siguiente sesión.

6.3 ¿Dónde entran los paquetes?

Un script puede utilizar funciones incluidas en R o funciones proporcionadas por paquetes adicionales. Como ya vimos cómo instalar y cargar paquetes, aquí solo necesitamos distinguir su papel dentro de un programa:

  • install.packages() prepara un paquete en nuestra computadora; no es una instrucción que debamos ejecutar cada vez que corremos el análisis.
  • library() permite utilizar las funciones de un paquete durante la sesión actual.
  • paquete::funcion() permite llamar una función específica indicando de qué paquete proviene.

Por ejemplo, más adelante leeremos archivos tabulares con readr::read_csv(). Para que un script sea fácil de reproducir, conviene que sus dependencias sean explícitas y que no intente instalar paquetes automáticamente cada vez que se ejecuta.

Código 
# Ejemplo de uso de un paquete dentro de un script:
# library(readr)
# datos <- read_csv("data_raw/muestras.csv")

# Alternativa sin cargar el paquete completo:
# datos <- readr::read_csv("data_raw/muestras.csv")

6.4 ¿Qué aporta un proyecto de RStudio?

Ya creamos un proyecto .Rproj y comprobamos su directorio de trabajo con getwd(). Su utilidad práctica aparece cuando comenzamos a tener varios scripts, archivos de entrada y resultados que deben mantenerse juntos.

Una organización sencilla podría ser:

analisis_secuencias/
├── analisis_secuencias.Rproj
├── data_raw/
├── scripts/
│   └── 01_revision_secuencias.R
├── results/
└── README.md

Dentro del proyecto podemos utilizar rutas relativas, como data_raw/muestras.csv, en lugar de rutas que solo funcionan en una computadora. No necesitamos volver a crear el proyecto ni cambiar el directorio con setwd() en cada script.

Cuando comencemos a guardar resultados, la carpeta results/ nos permitirá distinguir los archivos generados de los datos originales.

6.5 Ejecutar y revisar un script completo

Una buena prueba consiste en reiniciar la sesión de R y ejecutar el script desde la primera hasta la última línea. Esto permite detectar si el código utiliza objetos que solo existían porque los creamos antes en la consola.

Antes de considerar terminado un script, revisa que:

  • Las entradas estén definidas o se lean desde archivos identificables.
  • Las instrucciones estén en un orden lógico.
  • Los nombres de los objetos permitan reconocer su contenido.
  • Las funciones y paquetes necesarios estén identificados.
  • Los resultados se puedan obtener sin ejecutar comandos adicionales manualmente.
Advertencia🧠 Ejercicio 1

Considera el siguiente código, guardado en un archivo llamado revision.R:

Código 
longitudes <- nchar(secuencias)
resultado <- data.frame(id = ids, longitud = longitudes)
print(resultado)

Un estudiante afirma que el archivo funciona porque obtuvo una tabla al ejecutarlo en su computadora.

  1. ¿Por qué podría fallar si otra persona abre el archivo y lo ejecuta desde una sesión nueva de R?
  2. Modifica el script para que pueda ejecutarse completo sin depender de objetos creados previamente en la consola.
  3. ¿Qué cambiarías cuando los datos de entrada provengan de un archivo .csv?
TipSolución

El código depende de que secuencias e ids existan previamente. Si esos objetos no están definidos, la ejecución fallará.

Una versión independiente es:

Código 
# Datos de entrada
ids <- c("M01", "M02", "M03")
secuencias <- c("ATGCCG", "GGAT", "TTACGA")

# Verificación
stopifnot(length(ids) == length(secuencias))

# Procesamiento
longitudes <- nchar(secuencias)

# Resultado
resultado <- data.frame(id = ids, longitud = longitudes)
print(resultado)
   id longitud
1 M01        6
2 M02        4
3 M03        6

Si los datos estuvieran en un archivo .csv, sustituiríamos la creación manual de los vectores por una instrucción para leer el archivo desde una ruta relativa dentro del proyecto. Aprenderemos a hacerlo en la siguiente sesión.
